\section{システム全体アーキテクチャ}
本システムは,大別して3層からなるアーキテクチャで構成される（図\ref{fig:system}）.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=\linewidth]{src/system.png}
    \caption{システム全体アーキテクチャ}
    \label{fig:system}
\end{figure}
    
\subsection{全体構成}
\begin{enumerate}
\item \textbf{モバイルウェア層（ペリフェラルデバイス）}\\
Raspberry Pi Pico 2 W とMyoWareセンサーで構成される.sEMGの有効周波数帯域は20--500Hzとされており\cite{zheng2022},サンプリング定理を満たすため1kHzでADC変換を行う.このサンプリングレートをBLE Notifyの制約内で伝送するため,10サンプルずつパケット化してNotifyする.

\item \textbf{iOS層（ネイティブ実行環境）}\\
FlutterブリッジがMethod Channel / Event Channelを介してFlutter層と通信し,Neural Engine（Core ML）を用いた推論・on-device学習,ローカルストレージへのセッション永続化を担当する.

\item \textbf{Flutter層（アプリケーション層）}\\
BLE通信,データバッファリング,セッション管理を行うService層,UIを提供するView層,高速演算を担うC++/FFIライブラリ（特徴抽出）から構成される.
\end{enumerate}

\subsection{ファームウェア（Raspberry Pi Pico 2 W）}
MicroPythonベースのBLE Peripheral実装により,以下の機能を実装する.

\begin{itemize}
\item \textbf{サンプリング}：内蔵ADC4を用いた1kHz連続サンプリング
\item \textbf{パケット}  ：シーケンス番号（2バイト）+ 10サンプル（各4バイトfloat）の42バイト
\item \textbf{送信レート}：100Hz（10パケット周期）でNotify配信
\end{itemize}

\section{ソフトウェア構成}

\subsection{技術選定}
メインアプリケーションはGoogle社が開発したUIフレームワークであるFlutterを採用し,クリーンアーキテクチャに基づいて各処理をServiceとして定義し,Riverpodで状態管理する（図\ref{fig:flutter-arch}）.
Flutterは単一コードベースでiOS/Androidアプリを同時開発できるため,本研究では現時点でiOS向けの実装を行ったが,後述するService単位でのロジック分離により,Android対応への拡張が容易な設計となっている.
BLE通信,データバッファリング,特徴抽出などはプラットフォーム非依存のDartコードとC++コンパイルバイナリのFII呼び出しで実装し,機械学習推論部分のみをMethod Channel経由でNative層に委譲している.
Android対応時にはTensorFlow Lite実装をKotlinで追加することで,Flutter層を変更せずにAndroid版を構築できる.

\subsection{実装したServiceクラス群}
データフロー上の各処理をServiceクラスとして分離し,Riverpod Providersで依存性注入を行った.
以下に各Serviceの役割を示す.

\subsubsection{BleService（BLE通信）}
\label{subsubsec:ble-service}
\textbf{責務}：
Raspberry Pi Pico 2 WとのBLE通信の管理,sEMGデータの受信,データ配信.

\textbf{入出力}：
入力：BLE Notifyによる42バイトパケット  
出力：\texttt{BleDataPacket}のStream

\textbf{概要}：
\texttt{flutter\_blue\_plus}を用いてBLE Central機能を実装し,
デバイス名によるフィルタリング後に接続を行う.
カスタムUUIDのキャラクタリスティックをNotify購読し,
受信したパケット（シーケンス番号2B,サンプル10点40B）をパースして
Streamとして配信する（図\ref{fig:ble-flow}）.

\subsubsection{EmgWindowBuffer（データバッファリング）}
\label{subsubsec:window-buffer}
\textbf{責務}：
連続サンプル列を時系列ウィンドウに分割し,特徴抽出処理の入力を生成する.

\textbf{入出力}：
入力：連続するsEMGサンプル  
出力：150サンプル長のウィンドウ

\textbf{概要}：
内部バッファにサンプルを蓄積し,
150サンプル（150ms）のウィンドウを50サンプル（50ms）ホップで切り出す.
これにより2/3オーバーラップのウィンドウ系列を生成する（図\ref{fig:window-buffer}）.

\subsubsection{EmgMlService（推論・学習）}
\label{subsubsec:ml-service}
\textbf{責務}：
Flutter層とiOS Native層を接続し,推論およびon-device学習を実行する.

\textbf{入出力}：

Neural Engineを用いた推論を実行する.
また,\texttt{MLUpdateTask}を用いたon-device学習を行い,
更新後のモデルを永続化する（図\ref{fig:ml-architecture}）.

\subsubsection{EmgDatasetRecorder（データ記録）}
\label{subsubsec:dataset-recorder}
\textbf{責務}：
on-device学習に用いるラベル付き特徴量データを管理・保存する.

\textbf{入出力}：
入力：特徴量ベクトルおよびユーザ指定ラベル  
出力：\texttt{\{features, classLabel, timestamp\}}形式のデータセット

\textbf{概要}：
特徴量と対応ラベルをメモリ上に保持し,
JSON形式での保存および学習処理への受け渡しを行う.
収集データは\texttt{EmgMlService}の学習処理で直接利用できる形式とした.

\subsubsection{共通処理パイプライン}
推論およびデータ記録では,以下の処理を共通パイプラインとして用いる.
\begin{enumerate}
\item BleServiceから受信したパケットStreamを購読する
\item EmgWindowBufferで150ms窓を50msホップで切り出す
\item EmgFeatureExtractorで10次元特徴量を抽出し正規化する
\item EmgMlServiceで推論（および必要に応じて学習）を実行する
\end{enumerate}

\subsubsection{データの保存とエクスポート}
収集データセットはローカルストレージへJSON形式で保存し,
Share Sheet経由で外部へエクスポートできる.
オフライン解析や事前学習用データとしても利用可能である.
\subsubsection{on-device学習の実行}
\textbf{目的}：収集データを用いて端末上でモデルを更新し,個人差への適応を行う.\\
\textbf{使用Service}：EmgMlService,EmgDatasetRecorder.\\
\textbf{処理}：保存済みデータセットを学習用形式に変換し,
Method Channel経由でiOS Native層へ渡して\texttt{MLUpdateTask}により学習を実行する.
学習後のモデルは永続化され,次回起動時に自動ロードされる.
学習前後の性能変化は精度測定機能（図\ref{fig:accuracy-measurement}）により確認する.
\subsubsection{メモリクリア}
\texttt{CLEAR (memory)}ボタンにより,
メモリ上のデータセットを消去して新しいセッションを開始する.
異なる条件でのデータ収集を繰り返し実行できる.
